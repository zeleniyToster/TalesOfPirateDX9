# Arbah — база данных сервера

Аналог базы `piratia.arbah.ru`, собранный из таблиц **этого** сервера,
а не из выгрузки чужой версии игры. Предметы, монстры, NPC и таблица
опыта берутся напрямую из `server/GameServer/resource`, поэтому
ID всегда совпадают с тем, что есть в игре и в GM-командах.

## Что внутри

| Раздел | Данные |
|---|---|
| Предметы | 6337 позиций: ID, название, тип, цена, уровень, классы, стаки |
| Карточка предмета | иконка, описание, все бонусы, слоты, прочность, флаги, у кого продаётся |
| Монстры | 352 позиции из `monsterlist.txt` |
| Существа | 1650 существ из `CharacterInfo.txt` с настоящими ID |
| Спавны | 7590 точек из `<карта>monster_conf.lua`, с респауном и регионом |
| NPC | 482 позиции, из них 35 торговцев с ассортиментом (655 позиций) |
| Опыт | все 150 уровней: накопленный опыт и стоимость уровня |
| Калькулятор | боевые статы по формулам сервера |

В каталоге предметов у каждой позиции есть готовая GM-команда
`make <id>,1` — клик копирует в буфер обмена. Это и есть
то, ради чего проект затевался: ID не надо искать вручную.

Клик по строке предмета открывает полную карточку, клик по NPC —
его ассортимент, ссылка на NPC из карточки предмета ведёт туда же.


## Запуск на сервере

```bash
# из каталога arbah_project
docker compose -f docker-compose.arbah.yml up -d --build

# база будет доступна на http://127.0.0.1:8100
```

Контейнер встаёт в общую внешнюю сеть `pko_default`, поэтому другие
сервисы этой сети обращаются к нему как `http://arbah:8000`.
Порт наружу публикуется только на localhost — если база нужна
исключительно внутри Docker-сети, удалите блок `ports` из compose.

Если сети `pko_default` ещё нет:

```bash
docker network create pko_default
```

## Разработка на Windows

```powershell
cd arbah_project
.\.venv\Scripts\python.exe -m app.etl.coefficients
.\.venv\Scripts\python.exe -m app.etl.ingest

$env:PYTHONPATH="backend"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8100
```

Тесты:

```powershell
$env:PYTHONPATH="backend"
.\.venv\Scripts\python.exe -m pytest backend/tests -q
```

Документация API: <http://127.0.0.1:8100/api/docs>

## Обновление данных

Таблицы лежат в `data/`. После правки игровых `.txt` скопируйте их
и пересоберите базу:

```powershell
Copy-Item ..\server\GameServer\resource\ItemInfo.txt data\
Copy-Item ..\server\GameServer\resource\CharacterInfo.txt data\
Copy-Item ..\server\GameServer\resource\*monster_conf.lua data\spawns\
Copy-Item ..\server\GameServer\resource\script\MisScript\NpcScript*.lua data\npc\

$env:PYTHONPATH="backend"
.\.venv\Scripts\python.exe -m app.etl.ingest
```

На сервере то же самое — `docker compose ... up -d --build`.

Ресурсы клиента (иконки, текстуры) лежат **вне** проекта и в образ
не копируются: это десятки тысяч мелких файлов. Путь задаётся
переменной `ARBAH_ASSETS_DIR`, в compose — через `CLIENT_TEXTURE`:

```bash
CLIENT_TEXTURE=/opt/pko/Client/texture \
  docker compose -f docker-compose.arbah.yml up -d --build
```

## Про калькулятор

Формулы перенесены из `AttrCalculate.lua` (функция `ExAttrCheck`)
дословно, коэффициенты выгружаются из того же файла скриптом
`app.etl.coefficients`, поэтому расхождение с игрой исключено.

Калькулятор считает **«голого» персонажа** — без экипировки и баффов.
Вводите в него те же значения статов, что показывает игровое окно
характеристик. Если расхождение есть, сверять нужно только в этом
режиме; с надетым снаряжением формулы считают уже другие атрибуты
(`ATTR_ITEMC_*`, `ATTR_STATEV_*` и т.д.), и это отдельная работа.

Скорость передвижения и уклонение выводятся из состояний и экипировки,
поэтому в калькуляторе они всегда 0 — честнее, чем выдуманное число.

## Чего здесь нет

**Дроп с процентами.** В таблицах сервера его нет вообще — ни в
`.txt`, ни в `monster_conf.lua`, ни в C++. В `monsterhelp.lua`
есть только текстовые намёки («Rumored that X has a certain drop
rate»). Скриншот игрового окна с дропом помог бы разобраться,
в каком виде эта информация хранится на клиенте, но данные нужно
снимать с сервера, а не с картинки.

**Статичные картинки монстров.** В `Client/texture/character`
лежат в основном портреты игроков (`1.bmp`, `2.bmp`, ...), а
модели существ именуются иначе и однозначно не сопоставляются с
`CharacterInfo.txt` — проверено, совпадений 97 из 1650, и все
ложные. В карточке существа показывается заглушка.

**Расписание данжей.** В таблицах этого сервера его нет: ни в
`.txt`, ни в `GameDB.sql`. На оригинальном сайте это была
захардкоженная в PHP таблица ID инстансов оригинальной игры
(219, 220, 238…).

**Подключение к боевой MSSQL.** В `config.py` есть заготовка
`ARBAH_MSSQL_DSN`, но сейчас приложение работает только на SQLite.
Полезно было бы для отображения онлайна и рейтинга.

## Заметки по данным

* **Две нумерации монстров.** `monsterlist.txt` использует
  последовательные номера 1..352 — это список для дизайнера.
  `CreateCha` в спавн-конфигах использует настоящие ID персонажей
  (400..900). Связь идёт через `CharacterInfo.txt`: имя и ID берутся
  оттуда, уровень — из `monsterlist.txt` по имени (так находится
  338 из 352, у остальных уровень остаётся пустым).
* **Морские мобы без статичных точек.** Акулы и прочие существа
  из `monsterhelp.lua` есть в реестре, но не имеют `CreateCha` —
  они создаются по логике морских встреч. В поиске есть переключатель
  «только спавнящиеся», по умолчанию включённый.
* **`ItemInfo.txt` описан вручную.** Заголовок файла называет только
  первые 15 колонок и частично врёт. Реальная карта восстановлена из
  `CItemRecordSet::_ReadRawDataInfo`
  (`sources/Libraries/common/src/ItemRecord.cpp`) и лежит в
  `backend/app/etl/item_columns.py`. Важная деталь: моделей пять
  (`defITEM_MODULE_NUM = 5`), поэтому всё после них сдвинуто.
  Без этого цена читалась бы как «1», а уровень — как «1,2,3».
* **Слоты экипировки** пронумерованы по `enumEQUIP_*`: 5 — ожерелье,
  6 — левая рука, 9 — правая рука. Порядок неочевиденный.
* Названия типов предметов в `itemtype.txt` частично на китайском,
  переведены в `parsers.ITEM_TYPE_RU`.

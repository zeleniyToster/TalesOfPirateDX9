# ARBAH — база данных сервера

Сайт-справочник по игре, собранный из таблиц **этого** сервера. Аналог
`piratia.arbah.ru`, но с данными не из чужой версии игры, а из
`server/GameServer/resource` вашего репозитория.

Главная практическая ценность: **ID предметов и монстров для GM-команд**.
У каждого предмета в каталоге есть готовая команда `make <id>,1` —
клик по ней копирует её в буфер обмена.

Расположение: `arbah_project/`. Рабочий README с командами запуска —
`arbah_project/README.md`, этот файл описывает сам проект.

---

## Как это работает

```
Игровые .txt и .lua  →  ETL-парсеры  →  SQLite  →  FastAPI  →  браузер
   server/...            app/etl/      arbah.db    /api/*     статика
```

Данные читаются из игровых файлов при сборке базы и никуда не копируются
вручную. Ничего не выгружается с чужого сайта, ничего не заполняется руками.

| Слой | Технологии | Назначение |
|------|-----------|-----------|
| ETL | Python 3.13, только stdlib | разбор `.txt` и `.lua` в SQLite |
| API | FastAPI, uvicorn | поиск, карточки, калькулятор |
| Фронтенд | статические файлы, ES2020 | интерфейс без сборки и зависимостей |
| Развёртывание | Docker, python:3.13-slim | один контейнер, рядом с игровыми серверами |

Зависимостей ровно три: `fastapi`, `uvicorn`, `pydantic`. Node.js не нужен.

## Функциональность

### Каталоги

| Раздел | Источник | Объём |
|--------|----------|-------|
| Предметы | `ItemInfo.txt` | 6337 позиций |
| Монстры | `monsterlist.txt` | 352 позиции |
| Существа | `CharacterInfo.txt` | 1650 существ с настоящими ID |
| NPC | `npclist.txt` | 482 позиции |
| Опыт | `character_lvup.txt` | 150 уровней |
| Области и карты | `AreaSet.txt`, `mapinfo.txt` | 255 и 41 |

### Карточки

**Предмет** — иконка из ресурсов клиента, описание, все бонусы с
диапазонами, слоты экипировки, профессии, цена, размер стака, прочность,
отверстия, флаги (торгуется / подбирается / выбрасывается / уничтожается),
список продавцов с координатами.

**Существо** — уровень, число точек спавна, интервал респауна и таблица
областей обитания с рамкой (`20/19 - 522/527`). Полный список координат —
по кнопке, чтобы не загромождать карточку. Для монстров дополнительно
показываются **боевые характеристики** и **дроп**.

### Боевые характеристики

Лежат в `CharacterInfo.txt` — том же файле, что и реестр существ,
только в столбцах 60..90. Заголовок файла эти столбцы не описывает,
поэтому карта восстановлена и **сверена с панелью `Mob Info` клиента**:
двенадцать значений для `Killer Shroom` (ID 252) совпали с показанными
в игре — уровень 19, Max HP 457, атака 63–94, дефенс 43, точность и
уклонение 61, скорость атаки 2000, скорость бега 300, опыт 226.

Карта столбцов лежит в `app/etl/cha_columns.py`.

### Дроп

Тоже `CharacterInfo.txt`, столбцы **46** и **47**: в каждом до 15 значений
через запятую. Первая ячейка — ID предметов, вторая — частоты.
У `Killer Shroom`: `4345,4429,1655,3148,3388,0467,0643` и
`196,294,1428,1000,1428,100000,200000` — 7 предметов из 15 слотов,
остальные пустые.

**Частота хранится обратной**: 10000 соответствует 100 %. Клиент считает
`(10000 / частота) * g_DropBonus`, где `g_DropBonus` приходит с сервера.
На сайте частоты показываются **сырыми**, без пересчёта в проценты:
значение однозначно, а процент на сайте всё равно разошёлся бы с игрой
при любом рейте (проверялось: по сырым данным выходит 51.02 %, игра
показывает 50.00 %).

Запрос идёт по кнопке: клиент шлёт `CS_RequestDropRate`
(`UIStartForm.cpp:2226`), сервер отвечает `SC_RequestDropRate`, но
передаёт **только рейт** — сам список клиент берёт из `CChaRecord::lItem`.

Скриптовый переопределитель `g_chItemFall` (`Expand.h:1280`) в разбор
не включён: чтобы поддержать кастомных монстров, сделанных скриптом,
нужно парсить Lua поверх таблицы.

### Расписание данжей

В `<карта>/ctrl.lua` функция `can_open_entry_<карта>` сравнивает
`GetNowTime()` с часами открытия. Разобрано 25 карт, у 8 есть расписание,
17 открыты свободно.

| Карта | Файл | Вход |
|-------|------|------|
| Forsaken City | `abandonedcity` | 02, 06, 10, 14, 18, 22 |
| Dark Swamp | `darkswamp` | 02, 06, 10, 14, 18, 22 |
| Demonic World | `puzzleworld` | 02, 06, 10, 14, 18, 22 |
| Icicle Mirage | `binglang2` | 13, 19 |
| Thundoria Mirage | `leiting2` | 13, 19 |
| Shaitan Mirage | `shalan2` | 13, 19 |
| Chaos Argent | `garner2` | 04, 16 |
| Purgatory | `hell` | 15 |

Время серверное локальное — то же, что отдаёт `GetNowTime()`, поэтому
сверка идёт без поправки на часовой пояс. Спавн боссов в `DreamIsland`
(`os.date` с проверкой минут и секунд) сюда **не** относится: другой
механизм, на `can_open_entry` он не влияет.

**NPC** — карта, координаты, реплика торговца и ассортимент с иконками,
ценами и GM-командами. Работает для всех 482 NPC: у квестовых показывается
сообщение об отсутствии торговли.

### Калькулятор характеристик

Формулы перенесены из `AttrCalculate.lua` (функция `ExAttrCheck`) дословно.
Коэффициенты по 19 профессиям выгружаются из того же файла скриптом
`app.etl.coefficients` — 29 таблиц, поэтому рассинхрона с игрой нет.

Проверен вручную: мечник, уровень 1, CON=10 → `150 + 7 + 25 + 40 = 222`.
На этот случай есть тест.

Считает «голого» персонажа — без экипировки и баффов. Это единственный
режим, в котором результат можно сверить с сервером.

### Поиск

По названию и ID одновременно, фильтры по уровню, типу, региону,
фильтр «только торговцы». Инъекция через параметры сортировки закрыта
белым списком полей.

## Что нужно доработать

### Данных нет в серверных файлах

**Дроп и характеристики — НАЙДЕНЫ, сделаны.** Раньше искали в отдельной
таблице, а лежит оно в `CharacterInfo.txt` за пределами описанных
заголовком столбцов: дроп в 46–47, статы в 60–90. Подробности выше.

Что реально осталось недоступным:

**Картинки существ.** Имена ресурсов есть (`szIconName`), но сами
изображения в репозитории не лежат — их вытаскивать из клиентских
текстур отдельно.

**Локализованные названия дропа.** Названия предметов берутся из
`ItemInfo.txt`, поэтому часть записей остаётся на китайском.

### Технические долги

**Подключение к боевой MSSQL.** В `config.py` есть заготовка
`ARBAH_MSSQL_DSN`, но приложение работает только на SQLite. Пригодится
для показа онлайна и рейтинга.

**Изображения существ.** В `Client/texture/character` лежат в основном
портреты игроков, а модели существ не сопоставляются с `CharacterInfo.txt`:
проверено, совпадений 97 из 1650 и все ложные. В карточках стоит заглушка.

**Уровень монстров.** Есть только у 338 из 352 записей `monsterlist.txt` —
связь с реестром существ идёт по имени. У остальных уровень пустой.

**Локальные имена.** Названия предметов и NPC английские. Русские есть
в `StringSet.txt` (старая расшифровка лежит в `debug_files/binary_table/`),
но привязка индексов к сущностям не восстановлена.

**Обновление данных — решено.** Таблицы больше не копируются в
`arbah_project/data/` вручную: контейнер получает папку
`server/GameServer/resource` томом только для чтения, а база
пересобирается при старте контейнера. Полная пересборка занимает
**меньше секунды** (замерено: 0.56 с на полном наборе), поэтому после
правки дропа, предмета или расписания данжей достаточно:

```
docker compose restart arbah
```

или без перезапуска:

```
curl -X POST http://localhost:8100/api/admin/refresh
```

Пересборку образа для этого делать **не нужно** — она идёт по данным,
а не по коду. Образ `pko-arbah` пересобирается только при изменении
самого сайта.

## Развёртывание

Сервис `arbah` встроен в общий `docker-compose.yml`, образ собирается
один раз и дальше живёт своей жизнью.

```
docker compose build arbah      # один раз, при изменении кода сайта
docker compose up -d arbah
```

Тома:

| Том | Назначение |
|-----|-----------|
| `./server/GameServer/resource:/srv/resource:ro` | источник данных, только чтение |
| `./Client/texture:/srv/assets:ro` | иконки предметов и текстуры |
| `pko_arbah_db:/var/lib/arbah` | собранная база SQLite |

Именованный том `pko_arbah_db` переживает пересоздание контейнера,
поэтому база не пересобирается при каждом `docker compose up`.

Порядок запуска задаёт `entrypoint.sh`: сначала разбираются
коэффициенты из `AttrCalculate.lua`, затем собирается база, и только
после этого стартует веб-сервер. Если папка с таблицами не
примонтирована, контейнер падает с внятным сообщением, а не
молча показывает пустой сайт.

Обслуживание базы:

```
GET  /api/admin/refresh/status   # когда последний раз собиралась база
POST /api/admin/refresh          # пересобрать сейчас
```

Эндпоинты не защищены авторизацией и рассчитаны на локальную сеть:
они только перечитывают файлы и перезаписывают SQLite, игровые данные
не трогают. Если справочник выставляется в интернет, закройте маршрут
обратным прокси.

### Мелочи

- Карточка предмета не показывает ID в заголовке — есть только в GM-команде.
- В таблице координат спавна нет сортировки и поиска по области.
- Нет тёмной/светлой темы — только тёмная.

## Проверка целостности

34 теста, запуск:

```powershell
$env:PYTHONPATH="backend"
.\.venv\Scripts\python.exe -m pytest backend/tests -q
```

Тесты фиксируют не только текущее поведение, но и найденные ошибки:
привязку NPC по имени реплики вместо номера функции, деление координат
на 100 в рамке обитания, слот 9 как «правая рука», приоритет операторов
в поиске существ. Чтобы эти грабли не повторились.

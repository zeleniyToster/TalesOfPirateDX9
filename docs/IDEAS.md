## 1. Громкость звуков: убрать провал в первых делениях ползунка

Статус: **диагноз подтверждён, правка готова.** Баг найден при разборе жалобы «звук
пропадает, если недокрутить ползунок, потом резко становится громко».

### Что сделать

Одна строка в `sources/Client/src/DSoundManager.cpp:145`:

```cpp
int DSoundManager::VolumeToDB(double theVolume)
{
	int aVol = (int) ((log10(1 + theVolume*9) - 1.0) * 2333);
	if (aVol < -2000)
		aVol = -2000;      // ← БЫЛО: -10000
	return aVol;
}
```

Значение уходит в `SetVolume` в сотых долях децибела. Сейчас всё тише −20 дБ уходит в
−100 дБ, то есть в абсолютную тишину; с правкой получает −20 дБ.

### Почему именно это

Порог `vol ≈ 0.043` в пересчёте на пиксели ползунка шириной 98 px (33 деления, шаг 3 px)
попадает ровно на первые два деления:

| пиксель | деление | master | дБ сейчас | дБ с правкой |
|---|---|---|---|---|
| 0 | — | 0.0000 | −10000 (тишина) | −2000 (амплитуда 0.100) |
| 3 | 1-е | 0.0306 | −10000 (тишина) | −2000 |
| 6 | 2-е | 0.0612 | −1888 (0.114) | −1888 |
| 9 | 3-е | 0.0918 | −1722 (0.138) | −1722 |

Три деления подряд уходят в тишину, четвёртое выскакивает сразу на ~11% амплитуды —
это и есть «меньше двух делений пропадает, потом резко громко». Выше порога кривая
равномерная: шаг между соседними делениями ≈ +3% амплитуды, разрывов нет.

### Побочный эффект

Ползунок перестанет быть выключателем: на нуле будет тихо, но слышно. Если нужно настоящее
отключение — добавить проверку в обработчик ползунка `_evtMainMusicMouseDown`
(`UISystemForm.cpp:957`): `if (fPos <= 0) SetVolume(0)`. Правильнее решать это там, а не
в функции перевода громкости.

### Смежное, не трогаем

Громкость эффектов применяется дважды: `SetSoundSize(fPos/10)` и
`mSoundManager->SetVolume(fPos/10)`, а в `DSoundInstance::RehupVolume` они
перемножаются — `VolumeToDB(mBaseVolume * mVolume * mMasterVolume)`. Практически не
мешает, потому что кривая выше порога ровная. Отдельная задача на будущее.

### Отдельно про ini

`Client/user/system.ini` в `[audio]` хранит `musicEffect` и `musicSound`, клиент
перезаписывает файл сам, и при `musicEffect=0` на старте звук выключен до первого
движения ползунком. Если это мешает — ставить в ini разумные значения (например 10)
или чинить сохранение настроек.

### Работа

Три минуты. Пересборка клиента `Release|x86`. Сервер не трогаем.

## 2. Отдельный рейт опыта для квестов

Статус: **отложено по решению владельца проекта.** Описывает идею и всё, что к ней
относится, чтобы вернуться к вопросу позже без повторного разбора кода.

### Идея

Сейчас квестовый опыт и обычный kill-опыт идут **разными путями**, и рейты на них
распрострастраняются по-разному. Хочется, чтобы квесты имели собственный множитель,
независимый от `Server.Rates.Global.EXP`.

По аналогии с уже существующим ключом это выглядело бы так:

```lua
Server.Rates.Global.MissionEXP = 1    -- Rate at which missions grant experience.
```

## Почему сейчас нельзя просто покрутить

Разберём, что происходит с опытом от убийства монстра:

```
CEventHandler::Event_ChaDie            EventCalculate.cpp:14 / :128
  → GetExp_New                          exp_and_level.lua:72
    → ShareTeamExp                      exp_and_level.lua:166
      → GetPlyExpRate                   exp_and_level.lua:247   ← глобальный рейт
        → ExpSystem                      functions.lua:6628
            → Server.Rates.Map[...]      functions.lua:6635-6636
            → Server.Rates.Day[...]      functions.lua:6638-6639
            → кап по Server.Level.Limit  functions.lua:6641-6642
```

Квестовый опыт идёт мимо всего этого:

```
ActionsProc                            MisSdk/MissionSdk.lua:3473-3479
    p1 = p1 * GetExpState(character) / 100    ← это НЕ рейт
  → AddExp                              CharScript.cpp:726-776
    → CFightAble::AddExpAndNotic        FightAble.cpp:2014
      → CFightAble::AddExp              FightAble.cpp:1979-2012
        → setAttr(ATTR_CEXP, …)
```

То есть квестовый опыт умножается **только** на `GetExpState` — это
`CCharacter::m_ExpScale` (`Character.h:713-714`), инициализируется 100 и меняется через
`CMD_PM_EXPSCALE` как штраф за лаг (`GameAppNet.cpp:753-848`). Живых ветвей там только
`100`: значения `50` и `0` закомментированы, так что множитель сейчас всегда равен 1.

Дополнительно: в квестовом пути **не проверяется потолок уровня**, поэтому большой квест
может «перепрыгнуть» уровень.

## Где именно вставлять

Одна точка — `MisSdk/MissionSdk.lua:3477`, ветка `AddExp` внутри `ActionsProc`:

```lua
actions[i].p1 = actions[i].p1 * GetExpState(character) / 100
actions[i].p2 = actions[i].p2 * GetExpState(character) / 100
```

Предлагаемая правка по смыслу:

```lua
actions[i].p1 = actions[i].p1 * GetExpState(character) / 100 * MISSION_EXP_RAID
actions[i].p2 = actions[i].p2 * GetExpState(character) / 100 * MISSION_EXP_RAID
```

с объявлением рядом с остальными рейтами в `variable.lua:30-36` и алиасом в том же стиле,
что уже есть на строках 532-539:

```lua
-- Server Rates
EXP_RAID = Server.Rates.Global.EXP
MF_RAID  = Server.Rates.Global.DROP
SetGlobalRates(MF_RAID,EXP_RAID)
TEAM_EXP_RAID = Server.Rates.Global.TeamEXP
ELF_EXP_GET_RAID = Server.Rates.Global.FairyEXP
SHIP_EXP_RAID = Server.Rates.Global.ShipEXP
Resource_RAID_ADJUST = Server.Rates.Global.Resource
```

## Что обязательно учесть при реализации

Ветку `AddExp` в `ActionsProc` покрывает **не все** способы выдачи квестового опыта.
Те же мимо-рейты идут:

| Функция | Файл:строка |
|---|---|
| `AddExpAndType` | `MissionSdk.lua:3533` → `CharScript.cpp:778` |
| `AddExpPer` | `functions.lua:5822` |
| `AddExpAll` | `functions.lua:5831` |
| `AddExp_1..6` | `functions.lua:6937-7077` |
| `QianAddExp` | `functions.lua:3585` |

Все они пишут `ATTR_CEXP` напрямую. Чтобы рейт работал везде, множитель надо провести
через каждую, а не только через `ActionsProc`. Обратная сторона: `ExpSystem` вызывается
**только** из `ShareTeamExp`, то есть только из kill-опыта, — поэтому «исправить» всё
через `ExpSystem` нельзя.

## Похожий случай, который уже есть

`Server.Rates.Global.MissionGold` объявлен в `variable.lua:35` с комментарием
«The rate that the player receives gold from missions» — но **нигде не читается**. Это
заготовка под ту же идею, сделанная в прошлом и не доведённая до конца. При реализации
стоит либо задействовать, либо удалить, чтобы не путать.

## Квестовые предметы — отдельная история

`GiveItem` (`MissionSdk.lua:3642` → `CharScript.cpp:1178`) кладёт предмет прямо в
инвентарь, без шансов и без рейтов. Если нужен и отдельный рейт для квестовых предметов,
точка та же — ветка `GiveItem` в `ActionsProc`.

При этом дроп предметов **для** квеста идёт через рейт: вторая ветка `Check_Baoliao`
в `FightAble.cpp:2226` использует `GetPlyDropRate`.

## Оценка сложности

Правка на одну функцию `ActionsProc` — около часа работы. Полное покрытие всех шести
способов выдачи — ближе к двум-трём часам, плюс тестирование на сервере. Конфиг при этом
остаётся в `variable.lua`, пересборка не нужна.

## 3. Магазин: перенос в NPC или оплата игровым золотом

Статус: **отложено.** Задача из двух независимых частей, владелец проекта ещё не выбрал,
какая нужна.

### Что сейчас есть

Магазин (в коде `IGS`, в интерфейсе — 商城) открывается не через NPC, а отдельной
командой клиента:

```
PacketCmd_CS.cpp:941        packet.WriteCmd( CMD_CM_STORE_OPEN_ASK );
CharacterPrl.cpp:1133      case CMD_CM_STORE_OPEN_ASK
CharacterPrl.cpp:1158      pMainCha->SetStoreEnable(true);
```

Дальше все команды магазина уходят в Lua:

```
CharacterPrl.cpp:1165-1190  CMD_CM_STORE_LIST_ASK / BUY_ASK / CHANGE_ASK / QUERY / CLOSE / VIP
  → lua_getglobal("operateIGS") → lua_pcall
    → shop/init.lua:73  function operateIGS(Player, Packet)
```

Логика целиком в Lua, десять файлов в `server/GameServer/resource/script/shop/`:
`init.lua` (механика), плюс `apparels`, `crystals`, `equipment`, `fairy`, `forging`,
`grocery`, `leveling`, `mounts`, `tickets` (наполнение).

### Валюта: IMP, а не игровое золото

Это ключевой момент. Магазин торгует **не за золото**, а за отдельную валюту IMP:

```
shop/init.lua:40   function AddMallPack(title, description, price, hot, items, qty, stock)
shop/init.lua:45       Price = price,
shop/init.lua:117  WriteDword(Packet, Package.Price)
shop/init.lua:261  if not HasIMP(Player, Package.Price) then      ← проверка баланса IMP
shop/init.lua:299  TakeIMP(Player, Package.Price)                  ← списание IMP
```

В C++ валюта живёт отдельно от денег:

```
Character.h:140   int GetIMP() { return chaIMP; }
Character.h:868   int chaIMP;
Character.cpp:7609 void CCharacter::SetIMP(int impVal, bool sync) {
                      chaIMP = impVal < 2000000 ? impVal : 2000000;   ← потолок 2 000 000
```

То есть IMP — игровая валюта с потолком, которую, судя по всему, начисляли за покупки или
закидывали администратором. Клиент это видит как `labMoneyLeft` (остаток средств) и
`SetStoreMoney(long nMoBean, long nRplMoney)` в `UIStoreForm.h:135`.

### Вариант A: магазин за игровое золото

Самое простое, если устраивает потеря платёжного оборота. Тогда:

- заменить `HasIMP` / `TakeIMP` на операции с деньгами — вероятно `GetPlayer()` +
  атрибут золота, надо найти точное имя (в `CharTrade.cpp` деньги передаются как
  `dwMoney`, атрибут искать в `Libraries/common/include`);
- убрать потолок `2000000` — он был навязан реализацией IMP, для золота своя логика;
- в клиенте `UIStoreForm` перестать показывать остаток IMP;
- пересчитать цены во всех `.lua` из `shop/`: сейчас они в единицах IMP, при переходе на
  золото числа станут непригодны.

Оценка: основная работа — Lua и клиент, пересборка GameServer не нужна, клиент нужен.

### Вариант B: открыть магазин через NPC

Механика магазина не меняется, меняется только точка входа.

- В Lua добавить функцию открытия, вызываемую из диалога NPC — рядом с существующей
  `operateIGS`, чтобы клиенту уходило то же самое окно;
- в клиенте убрать/заблокировать вызов `CMD_CM_STORE_OPEN_ASK` (`PacketCmd_CS.cpp:941`),
  который сейчас инициирует открытие;
- в таблице NPC (`CharacterInfo.txt`) прописать нужного NPC.

Оценка: меньше, чем вариант A, если валюту оставляем IMP. Нужно найти механизм вызова
Lua из NPC-диалога — в проекте он есть, диалоги обрабатываются скриптами.

### Вариант A+B вместе

Не исключены: валюта — золото, точка входа — NPC. Тогда объём примерно складывается.

### Что нужно решить до начала

1. Какая валюта целевая — IMP или золото?
2. Магазин должен быть всегда доступен или только у конкретного NPC?
3. Что показывать игроку, если цена в IMP недостижима — сейчас просто отказ покупки.
